# centralize-local-infra-in-oops-infra

## Goal
Shared local dev/test infrastructure (Postgres, Redis, Floci) lives in one place — `oops-infra-v1/docker/` — instead of being owned by `oops-api-v1` alone. `oops-api-v1`'s `make dev` / `make test-up` work unchanged from the developer's point of view, just pointing at the new location. `oops-agent-v1` (once it exists) can connect to the same shared dev containers without duplicating compose files.

Done when:
- `oops-infra-v1` exists on GitHub (public, under `oopsla5xx`), initialized as a submodule of this workspace
- `oops-infra-v1/docker/dev/compose.yaml` and `oops-infra-v1/docker/test/compose.yaml` exist, matching what `oops-api-v1/docker/docker-compose.{dev,test}.yml` had (postgres + redis only — see Open questions re: Floci)
- `oops-api-v1/docker/docker-compose.dev.yml` and `docker-compose.test.yml` are deleted; `oops-api-v1/docker/docker-compose.prod.yml` stays (it's an app-deploy manifest for the `oops-api-v1` image, not shared infra — out of scope for this move)
- `oops-api-v1/Makefile` targets `docker-up`, `docker-down`, `docker-logs`, `test-up`, `test-down` reference the new `oops-infra-v1` path
- `oops-api-v1` CI workflow no longer references any compose file for test infra — uses GitHub Actions `services:` instead
- `oops-api-v1` README documents that local dev requires cloning via `oops-wiki-v1` (`git submodule update --init`)
- `PRD.md` §11 corrected: submodule (not symlink) terminology; Floci added to local stack

## Scope
- `oops-infra-v1` (new repo, submodule) — `docker/dev/compose.yaml`, `docker/test/compose.yaml`, `README.md`
- `oops-wiki-v1/.gitmodules` — fix `oops-infra-v1` URL to `git@github.com:oopsla5xx/oops-infra-v1.git`
- `oops-api-v1/docker/` — delete `docker-compose.dev.yml` and `docker-compose.test.yml` only; `docker-compose.prod.yml` stays untouched
- `oops-api-v1/Makefile` — update `docker-up`, `docker-down`, `docker-logs`, `test-up`, `test-down` targets
- `oops-api-v1/README.md` — add clone-via-wiki note
- `oops-api-v1/.github/workflows/*.yml` — replace compose-based test infra with `services:` blocks
- `oops-wiki-v1/PRD.md` §11 — terminology + Floci fix

## Out of scope
- Terraform (`oops-infra-v1/terraform/`) — no AWS environment needs managing yet
- `oops-agent-v1` — repo doesn't exist on GitHub yet (separate blocker, not part of this task); it will consume the shared compose once created, no changes needed there now
- `oops-web-v1` — has no docker-compose today, nothing to migrate
- `docker-compose.prod.yml` — it's an app-deploy manifest for the `oops-api-v1` image (no shared services inside), not "local dev/test infra". Stays in `oops-api-v1/docker/` untouched.
- Changing repo visibility conventions beyond what's stated (staying PUBLIC)
- `oops-agent-v1` GitHub repo creation
- Floci — not added in this task; nothing in `oops-api-v1` uses S3/SQS today (grep confirmed no hits), so adding it now would be speculative infra with no consumer. Add when `oops-api-v1` or `oops-agent-v1` actually needs AWS-service mocking.

## Test plan
- [ ] happy path: from a fresh clone of `oops-wiki-v1` with submodules initialized, `cd oops-api-v1 && make docker-up` brings up postgres+redis from `oops-infra-v1/docker/dev/compose.yaml`, API connects successfully via `make run`
- [ ] happy path: `make test-up` in `oops-api-v1` brings up the test containers from `oops-infra-v1/docker/test/compose.yaml` on the existing ports (5433/6380), `make test` passes against them
- [ ] edge case: `oops-api-v1` CI run (push to a branch) passes without any reference to `oops-infra-v1` — confirms the `services:` block fully replaces the old compose-in-CI dependency
- [ ] regression: no leftover reference to `docker-compose.dev.yml`/`docker-compose.test.yml` anywhere in `oops-api-v1` (Makefile, CI, README) after deletion — grep clean
- [ ] does not break: `oops-api-v1/docker/docker-compose.prod.yml` untouched (same content, same location)

## Constraints
- Must stay git submodule (not filesystem symlink) — confirmed in grill-me session
- `oops-wiki-v1` itself is currently not a git repo; this task does not change that
- Local dev workflow now *requires* cloning through `oops-wiki-v1` + `git submodule update --init` — standalone clone of `oops-api-v1` alone is no longer sufficient for local dev (accepted tradeoff)
- CI must not do cross-repo checkout of `oops-infra-v1` — use GitHub Actions native `services:` instead, accepting that image versions must be kept in sync by hand between `compose.dev.yaml` and the CI workflow file
- `oops-infra-v1` repo: PUBLIC visibility, matches `oops-api-v1`/`oops-web-v1` convention
- Floci (AWS local emulator, https://github.com/floci-io) is deferred — resolved as out of scope, see above

## Open questions
None — resolved during planning (see Out of scope).
